First RS1 candidate, B1 (checked in code 2026-10-28): `fabricate_chunk` searches for `stonehearth:build2:entities:chunk` entities owned by the work player (`fabricate_chunk_action.lua:24-31`). With no construction, which is most of a real game, every worker's finder exhausts the world and restarts every 2.5 s of real time. Chunks are created in three places (`new_chunk_node.lua:89`, `reduce_scaffolding_node.lua:71`, `scaffolding_set.lua:102`), all through `radiant.entities.create_entity` with an owner, and the engine fires `radiant:entity:post_create` and `radiant:entity:post_destroy` globally. A per-player set of live chunk ids kept from those events would let `_start_item_finder` wait for a chunk instead of searching. Open: whether `post_create` fires for entities restored from a save after the patch installs (the food decay service relies on it during load), and a benchmark phase without construction (the XL scenario keeps construction going in every town), for example `live_buildings=0`.

Not adopted: native pathfinding algorithm changes (JPS, HPA*, D* Lite, flow fields) are out of reach from Lua; parallel simulation is gated on the measured job-list share (Factorio FFF-215 found a parallel update slower than the serial one). `CatalogService:is_material` is already memoized per material string, so its remaining cost is the number of filter callbacks, which RS1 addresses.
